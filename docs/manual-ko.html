1Autumn 소개

Autumn은 코드가 아니라 계획을 중심에 둔 Windows용 IDE입니다. 노드 하나가 기능이나 작업, 모듈, 화면 같은 프로그램의 한 부분이고, 노드 본문에는 그 부분을 만들 AI에게 줄 지시를 적습니다. 파일 경로나 함수 형태, 데이터 구조처럼 꼭 지켜야 할 내용은 노드의 스펙 칸에 따로 적습니다.

기획이 끝나면 Claude Code, Codex CLI, Gemini CLI 같은 AI 코딩 도구를 MCP로 연결합니다. AI는 Autumn이 정리한 빌드 계획을 받아 순서대로 코드를 쓰고, 끝낸 노드를 완료로 바꿉니다. 그 변화는 캔버스에 바로 보입니다.

모든 데이터는 내 컴퓨터에만 있습니다. 서버나 계정이 없고, Autumn은 API 키를 저장하지 않습니다. AI 도구는 원래 쓰던 로그인을 그대로 씁니다. 프로젝트는 WorkFlow 폴더에 JSON 파일로 저장되므로 백업하기도 쉽습니다.

2설치

Autumn.exe 하나로 쓰기

GitHub에서 받은 Autumn.exe는 파일 하나로 된 프로그램입니다. 받은 파일을 실행하면 됩니다. 처음 실행할 때만 %LOCALAPPDATA%\Autumn에 프로그램을 푸느라 몇 초 걸리고, 그다음부터는 바로 켜집니다. 이때 프로젝트는 문서\Autumn\WorkFlow에 저장됩니다.

zip으로 받은 경우

  1. zip 파일을 원하는 곳(예: 바탕 화면)에 풉니다.
  2. Autumn 폴더 안의 Autumn.exe를 실행합니다. 따로 설치하는 과정은 없습니다.
Autumn\
  Autumn.exe              Autumn 실행
  Autumn 사용설명서.pdf    이 설명서
  WorkFlow\               내 프로젝트(*.autumn.json), 다시 빌드해도 그대로 유지
  app\                    실행 환경(Electron)
  Source\                 소스 코드
처음 실행할 때 Windows가 "PC 보호" 창을 띄우면 추가 정보를 누른 다음 실행을 누르세요. 코드 서명을 하지 않은 프로그램이라 나오는 안내입니다.

소스에서 빌드하기

Node.js 18 이상이 필요합니다. Source 폴더의 Build.bat을 실행하면 바탕 화면에 Autumn 폴더가 만들어지고, 이미 있으면 새 버전으로 바뀝니다. WorkFlow 폴더는 건드리지 않습니다.

처음 빌드할 때만 Electron과 빌드 도구를 %LOCALAPPDATA%\Autumn-build에 내려받습니다. 한국어로 시작하는 빌드는 node scripts/build.js --lang=ko로 만들고, 다른 폴더에 만들려면 --out=D:\Apps\Autumn처럼 위치를 지정합니다.

화면 언어 바꾸기

오른쪽 위의 English / 한국어 버튼이나 보기 메뉴의 언어에서 바꿉니다. 창이 한 번 다시 열리면서 바뀌고, 다음에 실행할 때도 그대로 유지됩니다.

4프로젝트 만들기

  1. 시작 화면의 새 프로젝트를 누르거나 Ctrl+N을 누릅니다.
  2. 이름을 적고 만들기를 누르면 WorkFlow 폴더에 이름.autumn.json 파일이 생깁니다. "시작 노드와 기본 AI 규칙을 넣어서 시작"을 켜 두면 두 노드가 미리 들어갑니다.
  3. 시작 노드에 목표, 기술 스택, 출력 폴더, 실행 명령을 적습니다. AI는 출력 폴더에 코드를 씁니다.
처음이라면 시작 화면의 예제 프로젝트 둘러보기로 할 일 앱 예제를 열어 보세요. 이 설명서의 그림도 대부분 그 예제입니다. 프로젝트는 자동으로 저장됩니다. 아직 파일 위치가 정해지지 않았으면 임시로 저장해 두었다가, 처음 저장할 때 위치를 묻습니다.

5노드와 연결

노드 다루기

  • 왼쪽 목록에서 노드를 끌어다 놓거나, 캔버스 빈 곳을 더블클릭하거나, 툴바의 노드 추가를 누르면 노드가 생깁니다.
  • 노드 오른쪽의 동그란 출력 포트를 다른 노드로 끌어다 놓으면 연결됩니다. 연결 종류는 두 노드를 보고 자동으로 정해지며, 연결을 선택해서 바꿀 수 있습니다.
  • 여러 노드를 선택하고 Ctrl+G를 누르면 그룹이 됩니다. 그룹에 연결하면 그룹 안의 모든 노드에 연결한 것과 같아서, 프롬프트 하나를 화면 전체에 적용할 때 편합니다.
  • 노드를 더블클릭하거나 Enter를 누르면 제목과 프롬프트를 고칠 수 있습니다. 나머지 항목은 오른쪽 속성 패널에서 고칩니다.
  • 이미지는 노드에 끌어다 놓거나 Ctrl+V로 붙여 넣습니다. 설정값, 상수, 샘플 데이터는 속성 패널의 데이터 칸에 넣습니다.

6프로그래밍 언어 노드

AI가 어떤 언어로 코드를 쓸지 정하는 노드입니다. 속성 패널의 목록에서 언어를 고르고, 필요하면 버전과 프레임워크, 코드 스타일을 적습니다. 고를 수 있는 언어는 JavaScript, TypeScript, Python, C#, C++, C, Java, Kotlin, Go, Rust, Swift, Dart, PHP, Ruby, Lua, GDScript, HTML / CSS, SQL, PowerShell, Bash, 기타입니다.

아무 데도 연결하지 않으면 프로젝트 전체에 적용되고, 빌드 계획의 프로젝트 설정에 들어갑니다. 특정 노드나 그룹에 연결하면 그 부분에만 적용됩니다. 서버는 Python, 화면은 TypeScript처럼 나눠 쓸 수 있습니다.

7결과 노드

결과 노드는 중간 점검용 노드입니다. 확인하고 싶은 단계를 결과 노드로 연결해 두면, 그 단계까지 실행했을 때 무엇이 나오는지 AI가 판단해서 채워 줍니다.

결과 받기

  1. 결과 노드의 기대 결과 칸에 나와야 할 내용을 적습니다. 확인 방법(예: npm test)도 적어 두면 좋습니다.
  2. 속성 패널의 결과를 맡길 AI에서 Claude Code, Codex, Gemini CLI 중 하나를 고릅니다. 이 컴퓨터에 설치된 것만 보이고, 고른 AI는 결과 노드마다 따로 기억됩니다.
  3. AI에게 결과 요청을 누릅니다. 보통 5~15초 걸리고, 기다리는 동안 노드에 경과 시간이 표시됩니다. 취소를 누르면 멈춥니다.

답이 오면 결과 노드에 상태와 한 줄 요약, 출력, AI 설명이 채워집니다. 상태는 ✓ 통과 ✗ 실패 ▸ 출력 ≈ 예측 중 하나입니다. AI는 코드를 실제로 실행하지 않고 읽어서 판단하기 때문에, 이렇게 받은 결과에는 '예측'이라고 표시됩니다. 내용은 직접 고쳐 적어도 됩니다.

결과가 틀렸을 때

AI는 결과 노드 앞의 단계를 고치지 않습니다. 결과가 틀리면 결과 노드 바로 옆에 이슈 노드를 만들어 연결하고, 고칠 점만 한 줄씩 적습니다.

print(안녕하세요) → print("안녕하세요")

단계를 고친 뒤 다시 요청해서 통과하면 그 이슈는 완료로 바뀝니다. 또 틀리면 새 이슈를 만들지 않고 같은 이슈를 다시 엽니다.

실제로 실행해 보고 싶을 때

요청 문장 복사를 눌러 터미널의 AI에게 붙여 넣으세요. 그 AI가 프로그램을 실행한 뒤 autumn_report_result로 결과를 보고하고, 고칠 점은 같은 방식으로 이슈 노드에 정리됩니다.

동작 방식

MCP는 AI가 Autumn을 부르는 방향으로만 동작해서, Autumn이 터미널에 있는 AI에게 먼저 말을 걸 수는 없습니다. 그래서 결과 요청 버튼은 고른 AI 도구를 백그라운드에서 한 번 실행하고 질문을 넘깁니다. Claude Code는 모든 도구를 끈 상태로, Codex는 읽기 전용으로 실행되므로 파일을 바꾸지 못합니다. 질문에는 결과 노드로 이어진 단계의 내용이 들어가고, 사용하는 AI 서비스의 사용량이 조금씩 듭니다.

실행(F11)이 끝나면 결과 노드의 통과와 실패 개수가 함께 표시되고, 실패한 결과는 경고 목록에 올라갑니다.

8빌드 계획

AI는 캔버스를 직접 보지 않습니다. Autumn이 노드를 정리해서 만든 빌드 계획(Markdown)을 읽습니다. 빌드 계획은 다음 순서로 만들어집니다.

  1. AI 규칙 노드의 내용이 맨 앞에 나옵니다. AI는 모든 작업에서 이 규칙을 따릅니다.
  2. 이어서 프로젝트 설정이 나옵니다. 시작 노드의 목표, 기술 스택, 출력 폴더, 실행 명령, 제약 조건과 연결되지 않은 프로그래밍 언어 노드의 설정입니다.
  3. 시작 노드에서 출발해 흐름, 유발, 필요 연결을 따라가며 단계에 번호를 붙입니다. 분기나 조건처럼 갈라지는 곳은 "다음: [참] …"처럼 포트 이름과 함께 적힙니다.
  4. 단계마다 그 단계에 연결된 것이 함께 붙습니다. 적용되는 프롬프트와 AI 노트, 언어 노드, 먼저 끝나야 하는 단계, 사용하는 것, 다음 단계, 참고 문서입니다. 그룹에 연결된 것은 그룹 안의 모든 노드에 붙습니다.
  5. 흐름 밖에 있는 모듈, 함수, API, 데이터 모델, 화면은 구성 요소로 따로 정리되어 경로와 시그니처가 지켜지도록 합니다.
  6. 결과 노드는 점검 지점으로 들어가고, 마지막 결과와 AI 설명도 함께 적힙니다.
  7. 마지막에 메모, 문서, 따로 떨어진 프롬프트가 참고 자료로 붙습니다.

## 이 계획을 쓰는 방법

아래에 설명된 프로그램을 만드는 것이 당신의 일입니다. 사람이 Autumn에서 노드로 설계했고, 모든 노드는 프롬프트나 스펙입니다.

1. **AI 규칙**을 먼저 읽고 모든 단계에서 따르세요 — 다른 무엇보다 우선합니다.
2. 코드는 **~/Desktop/todo-app**에 쓰세요 (폴더가 없으면 만드세요). 단계에 따로 지정이 없으면 **JavaScript (Node 20 · Electron)**(으)로 작성하세요.
3. **단계를 순서대로** 구현하세요. 단계 아래 적힌 프롬프트와 AI 노트는 그 단계에만 적용되고, "필요"는 먼저 해야 합니다.
4. **구성 요소**(모듈, 함수, API, 데이터 모델, 화면)는 단계들이 만들거나 쓰는 부품입니다 — 경로, 시그니처, 스키마를 지키세요.
5. 비밀값(API 키, 토큰, 비밀번호)을 절대 코드에 넣지 마세요. 환경 변수나 git에 올라가지 않는 설정 파일에서 읽으세요.
6. Autumn MCP 서버가 연결되어 있으면 단계를 끝낼 때마다 `autumn_update_node`로 상태를 "done"으로 바꾸고, 해결하지 못한 것은 Issue 노드로 추가하세요.

## ⚠ AI 규칙 — 모든 작업에서 반드시 따를 것

### AI 규칙

- 코드를 쓰기 전에 AI 규칙과 빌드 계획 전체를 읽고, 시작 노드부터 흐름을 따른다.
- 노드에 적힌 대로 정확히 만든다. 불분명하면 추측하지 말고 묻는다.
- 비밀값(API 키, 토큰, 비밀번호)을 절대 코드에 넣지 않는다. 환경 변수나 git에 올라가지 않는 로컬 설정에서 읽는다.
- 읽기 쉽게 쓰고 주석을 단다. 기존 스타일을 따른다.
- 노드를 구현하면 상태를 완료(done)로 바꾼다.

**절대 하지 말 것**

비밀값 하드코딩 · 묻지 않고 의존성 추가

**기본 모델 / 도구**

Claude Code · Codex

**기본 설정**

Node 20 · npm · Windows 11

9흐름 확인과 실행

이어진 노드 보기

노드를 클릭하면 그 노드로 들어오는 앞 노드는 금색, 나가는 뒤 노드는 주황색으로 빛나고, 관계없는 노드는 흐려집니다.

흐름 추적

T를 누르면 선택한 노드의 앞쪽 흐름과 뒤쪽 흐름 전체가 단계별로 표시됩니다. 위쪽 막대에서 앞쪽만, 또는 뒤쪽만 볼 수도 있습니다.

실행

F11이나 P를 누르면 빛이 시작 노드에서 출발해 연결을 따라 2초에 한 단계씩 나아갑니다. 갈림길에서는 빛이 나뉘어 모든 갈래를 동시에 지나갑니다. 속도는 2초, 1초, 0.5초 중에서 고를 수 있고 Esc로 멈춥니다. 화면을 축소해도 글자는 그대로 보입니다.

실행이 끝나면 한 번도 도달하지 못한 노드, 아무 데로도 이어지지 않는 갈래, 실패한 결과를 목록으로 보여 줍니다. 항목을 누르면 그 노드로 이동합니다.

10AI 연결

오른쪽 위의 AI 연결을 누르면 이 컴퓨터의 경로가 들어간 명령이 나옵니다. 터미널에 한 번만 입력하면 되고, Autumn에 들어 있는 실행 환경을 쓰기 때문에 Node.js가 없어도 됩니다.

# Claude Code
claude mcp add autumn -s user -e ELECTRON_RUN_AS_NODE=1 -- "…\Autumn\app\Autumn.exe" "…\Autumn\app\resources\app\mcp\server.js"

# Codex CLI
codex mcp add autumn --env ELECTRON_RUN_AS_NODE=1 -- "…\app\Autumn.exe" "…\app\resources\app\mcp\server.js"

# Node.js가 있으면 어떤 MCP 클라이언트에서든
node "…\app\resources\app\mcp\server.js"

AI로 만들기

툴바의 AI로 만들기를 누르면 AI에게 줄 요청 문장과 빌드 계획이 준비됩니다. 코드를 만들 폴더에서 터미널을 열고 AI에게 이렇게 말하면 됩니다.

"autumn" MCP 서버를 사용해서 프로젝트 "할 일 앱"의 autumn_build_plan을 호출하고, 계획대로 프로그램을 만들어 줘.
AI 규칙을 지키고, 끝난 노드는 상태를 "done"으로 바꿔 줘.
MCP를 연결하지 않았다면 빌드 계획 복사로 계획을 복사해서 아무 AI 채팅에나 붙여 넣어도 됩니다.

11MCP 도구

AI가 쓰는 도구들입니다. 모두 autumn_으로 시작합니다. 프로젝트는 이름("할 일 앱")이나 파일 경로로 지정하고, 생략하면 Autumn에 열려 있는 프로젝트를 씁니다.

파일 메뉴의 내보내기에서 고릅니다.

14문제 해결

AI가 Autumn을 찾지 못합니다

AI 연결 창의 명령을 다시 입력하고 AI 도구를 새로 시작하세요. Autumn 폴더를 옮겼다면 경로가 바뀌었으므로 다시 등록해야 합니다.

AI가 고친 내용이 화면에 보이지 않습니다

AI가 같은 프로젝트 파일을 쓰고 있는지 확인하세요. AI에게 autumn_status를 호출하게 하면 어떤 파일을 쓰는지 알려 줍니다.

결과 요청을 눌러도 답이 오지 않습니다

"AI 도구를 찾지 못했습니다"가 나오면 Claude Code, Codex, Gemini CLI 중 하나를 설치하고 로그인한 다음 Autumn을 다시 켜세요. 응답에 실패하면 그 AI가 알려 준 이유(로그인 필요, 사용량 한도 등)가 메시지로 나옵니다.

실행(F11)에서 "도달하지 못함" 경고가 나옵니다

시작 노드에서 흐름 연결로 이어지지 않은 노드입니다. 연결을 추가하거나, 참고용 내용이라면 문서나 메모 노드로 바꾸세요.

프로젝트 파일은 어디에 있나요?

Autumn\WorkFlow 폴더에 있습니다. 다시 빌드하거나 새 버전으로 바꿔도 이 폴더는 그대로입니다. 새 버전으로 옮길 때는 WorkFlow 폴더만 복사하면 됩니다.

15보안과 라이선스

  • Autumn에는 API 키, 토큰, 비밀번호가 들어 있지 않습니다. AI 도구는 각자의 로그인을 씁니다.
  • 새 프로젝트의 기본 AI 규칙에는 "비밀 값을 코드에 넣지 말고 환경 변수나 git에 올라가지 않는 설정 파일에서 읽을 것"이 들어 있습니다.
  • Autumn 자체는 인터넷에 접속하지 않습니다. 노드 내용이 AI 회사로 전달되는 것은 사용자가 직접 쓰는 AI 도구를 통해서뿐입니다.
  • 노드에는 비밀 키를 적지 마세요. 노드 내용은 빌드 계획과 내보낸 문서, AI에게 보내는 질문에 들어갑니다.
